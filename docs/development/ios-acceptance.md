# TestFlightの通し試験

実施状況は未実施。配布候補をTestFlightから2台のiPhoneに入れ、別々のアカウントで招待から月別の振り返りまでを1回通す。対象の挙動と、試験時点で確定している条件は初回リリース仕様を参照する。 [初回リリース仕様](../../spec.md) · [RCNO-33](https://atsushi0130.atlassian.net/browse/RCNO-33)

## 試験前の準備

1. 端末Aと端末Bに、対象のTestFlightビルドをインストールする。ビルド番号、端末機種、iOSのバージョン、使用するSupabase環境を記録する。 [iOSの配布準備](ios-distribution.md)
2. 試験用のメールアドレスを2つ用意する。端末Aを招待する側、端末Bを招待される側とし、端末Bはサインアウトした状態から始める。試験の投稿には共有できる写真を使う。
3. 週次切替の予定時刻と、締切済みのボードが退色する条件を仕様で確認する。通し試験は週次切替をまたいで実施する。退色の確認が後日になる場合は再開日時を記録し、同じボードを追跡する。

## 手順と合格条件

| 番号 | 操作 | 合格条件 |
| --- | --- | --- |
| 1 | Aでメールアドレスとパスワードを使ってサインインし、試験用グループを作る。Aで招待リンクを共有し、サインアウト中のBで開く。Bは別のメールアドレスとパスワードでサインインする。 | Bは認証後に招待受付へ戻り、Aと同じグループに参加できる。Bがリンクを開き直しても所属が重複しない。 |
| 2 | 両端末でグループを開き、お題と締切を照合する。Bで通知を許可してアプリをバックグラウンドに移し、変更権限を持つAが自由入力のお題を保存する。Bは届いた通知を開く。 | 両端末に同じ開催中のお題が1件表示され、締切は同じ時点を指す。変更後にBへプッシュ通知が届き、タップすると対象グループのボードが開く。 |
| 3 | Aでアプリ内カメラを使い、撮影した写真を投稿する。Bはライブラリの写真を1枚投稿する。仕様で定めた操作で、それぞれ異なる都市を写真に紐付ける。 | 両端末で2枚の写真を開ける。都市別マップに2都市が表示され、各都市から該当する写真だけを開ける。 |
| 4 | BがAの投稿写真をボード上で移動する。編集中にAでBの参加者表示とカーソルを確認する。Bは移動を確定し、編集画面を離れる。 | AでBのカーソル位置と写真の移動を確認できる。編集が終わるとBのカーソル表示が消え、確定した配置が両端末で一致する。 |
| 5 | AとBで文字・スタンプ・ペンの線を合計1つずつ追加する。両端末で表示を照合してからアプリを閉じ、再起動する。 | 再起動後も各アカウントで同じグループを開ける。写真の配置と3種類の装飾が両端末で復元される。 |
| 6 | 週次切替後、両端末で開催中のお題を開く。月別の振り返りから先ほど編集したボードを開き、新規投稿や配置・装飾の変更ができるか確認する。 | 次のお題が両端末に1件表示される。締め切ったボードは対象月から開け、保存した編集内容を閲覧できる。新規投稿と配置・装飾の変更はできない。 |
| 7 | 仕様上の退色条件を満たしたら、そのボードを両端末で開く。次にAが自分の写真を取り下げ、Bでボードを開き直す。 | ボードが仕様どおりに退色して見える。Aが取り下げた写真はBのボードから消え、Bが投稿した写真は残る。 |

## 実施記録

| 項目 | 記録する内容 |
| --- | --- |
| 実施日時と実施者 | 開始・終了の日時、タイムゾーン、端末AとBの担当 |
| アプリと接続先 | TestFlightのバージョンとビルド番号、コミット、仕様の版、Supabase環境名 |
| 端末と試験データ | AとBの機種とiOS、アカウントの識別名、グループとボードのID、通知設定と切替時刻 |
| 各手順の結果 | 手順番号、合格・不合格・実施不可・未実施、観測した結果、確認時刻、証跡リンク |
| 再試験 | 不具合のJira課題、再現手順、修正ビルド、再試験の結果。実施不可の項目は不足条件と再開時期 |

招待後の画面、通知の到着と遷移、2端末の同期と再起動後の表示、都市別マップ、切替前後と退色の画面を記録する。取得できる場合は、通知イベントIDや切替処理の結果も添える。証跡を共有する前にメールアドレス、招待URL、認証情報、端末トークンが写っていないことを確認する。

全手順の挙動を対象ビルドで確認できた時点で、通し試験を合格とする。TestFlightビルド、iPhone、接続先、仕様のいずれかがそろわない手順は実施不可として理由を残す。未実施の項目は未実施のまま記録し、RCNO-33の受け入れは保留する。
